# 原型先行 — 完整约定（从两个生产实例提炼）

实例 1：ai_quality_analysis `design/`（2026-08 起，源头）；实例 2：skills 仓
`services/code-loop/prototypes/`（2026-09-17 引入并演进）。本文件是 skill 的约定权威，
SKILL.md 只保留工作流主干。

## 1. 目录与唯一源

- 默认 `design/`；项目已有惯例如 `prototypes/` 从其惯例。
- **唯一设计与版本源**，随 git 版本控制。不向任何外部设计工具（Open Design 等）同步
  渲染副本——实例 1 曾维护双副本，2026-08-14 已解耦：外部副本必然漂移，历史教训。
- 评审用的手绘标注/截图存 `drawings/`（可选），只归档不演进。

## 2. 原型形态

- 纯静态 HTML + CSS + 原生 JS，**无构建依赖**，浏览器双击即开（相对路径引用 assets）。
- 假数据内联在页面 `<script>` 中，不引外部数据源、不发真实请求。
- 高保真：视觉 token（配色/字体/间距/组件样式）与实现主题一致，避免「原型示意 ≠ 实现」
  的视觉落差——用户确认的是将要做出来的东西。
- 需要与实现同款图表效果时，可 vendored 第三方库进 `assets/`（见 §5）。

## 3. 一改动一文件

- 一个视图 / 一次改动一个文件，命名与实现的视图/路由名一致
  （`report.html` ↔ `/report`、`run-detail.html` ↔ `view=run`）。
- 改同一个已实现视图时改同一个原型文件出增量，不为每次改动新开文件。

## 4. 页面头注释（check WARN 兜底）

每页顶部写明三要素，让任何会话打开原型即知上下文：

```html
<!-- proto:
需求: <对应 issue/spec 或一句话需求>
入口路径: <实现的路由/入口，如 /report 或 view=run>
数据契约: <新增后端接口则在此定义；纯展示写 无>
-->
```

## 5. 共享 assets 与 vendored 库

- `assets/` 放共享样式与脚本（顶栏导航、图表渲染、弹窗等跨页复用件）。
- vendored 第三方库与实现**同版本**，文件名旁注版本；HTML 引用带 `?v=<日期或版本>`
  查询串防缓存。升级实现侧依赖时同步替换 assets 内的副本。
- check_design.py 对 README 中无 `?v=` 的 assets 引用给 WARN。

## 6. README 清单表（check 的校验对象）

四列固定语义：

```markdown
| 页面 | 文件 | 状态 | 对应实现 |
|---|---|---|---|
| 质量报表 | `report.html` | 已确认并实现（2026-09-10） | `/report` 页面 + `app/api/report.py` |
```

- **页面**：人话名称；**文件**：反引号包 .html 文件名（校验按此列双向比对磁盘）；
  **状态**：词汇表三值（待确认/已确认/已确认并实现）+ 可选括号备注；**对应实现**：
  落地后的入口（路由、组件、API），未实现写 未开发。
- 一个文件只允许一行；改动前后跑 check_design.py 保持双向一致。

## 7. 状态流转与 spec 联动

- 出稿/更新 → `待确认`；用户确认 → `已确认`，同时 spec/plan 的状态行或关联字段写明
  「原型 design/xxx.html 经用户确认」——原型确认事实进入方案文档，评审可追溯；
  实现落地 → `已确认并实现（日期）`。
- spec 中把「原型经用户确认」列为前置硬门禁条款（实例 1 的 spec 均如此写）。

## 8. 确认后不删除

原型是该视图的设计事实源。后续改同一视图，仍先改原型再确认再动实现；删除原型等于
销毁设计基线。仅当视图被彻底移除时随实现一并删除（清单行同步移除）。

## 9. 演进基座（多视图项目的进阶形态，实例 2 演进出）

视图多、跨视图联动多的项目，可把 `index.html` 做成**完整 dashboard 可交互副本**
（hash 路由 + 全部视图壳可点击），此后所有原型增量都基于该完整页面演示，不再新增
单视图迷你原型；存量单视图文件保留为各自已实现视图的设计事实源，不再演进。
适用判据：新改动需要演示跨视图联动/深链走查时。

## 10. 非运行时代码

原型目录随服务/项目源码走 git，但**不是**运行时代码：web 服务不路由它、自动化测试
不加载它、打包不包含它。它是给人和确认流程看的设计资产。

## 11. 口径同步

原型内容以项目 docs/（spec/设计文档）为口径基准；文档口径变更时同步更新原型页，
保持两者一致。原型与文档冲突时，以文档为准改原型，而不是留着两套说法。

## 12. 本地预览

双击打开（相对路径引用 assets 时可用）；批量浏览起静态服务：

```bash
cd design && python -m http.server 8765
```
