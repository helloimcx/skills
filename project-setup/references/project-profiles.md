# 项目形态

只读取并应用与当前项目有关的部分。多个形态并存时，先确定一个最小主路径，再组合必要边界；不要为了覆盖本文件而初始化未被需求支持的组件。

## Service / API

最小垂直切片从真实协议入口进入，经过应用用例，到达必要适配器并返回稳定响应。

- **边界**：transport/controller 只处理协议、验证和映射；业务规则不依赖 Web 框架。
- **错误**：对外使用稳定 `code`/`message`，HTTP/RPC 状态映射集中管理；内部保留 cause、stack、`trace_id`。
- **测试**：领域/用例 Unit；路由、序列化、DB 或外部适配器 Integration；启动真实服务并调用公共协议的 E2E；Bug Regression。
- **可观测性**：请求入口/出口、状态变化、外部调用和耗时；跨层传递 trace。
- **安全**：输入限制、认证与授权边界、CORS/CSRF/SSRF、速率与资源上限按威胁模型处理。
- **数据**：若有写入，明确事务、幂等、迁移与回滚；不要为只有内存行为的初始切片预建数据库。

## Web / UI

最小垂直切片必须能从真实用户入口操作并观察结果，而不只是渲染静态占位页。

- **边界**：页面/路由组合功能，feature 模块拥有行为，UI primitives 不承载业务规则，API client 统一处理协议和错误。
- **状态**：区分服务端、远程、表单和本地 UI 状态；避免隐式全局状态。
- **测试**：纯逻辑与关键组件 Unit；路由、状态和 API 边界 Integration；浏览器公共路径 E2E；Bug Regression。
- **可访问性**：语义 HTML、键盘路径、焦点、标签和错误提示从初始组件开始检查。
- **安全**：输出编码、XSS、CSRF、开放重定向、敏感缓存和 token 存储遵循框架安全默认值。
- **构建**：验证生产 build、静态资源路径、运行时配置注入和刷新/深链接行为。

## CLI

把 CLI 当作公共接口。最小垂直切片解析真实参数、调用独立用例并通过 stdout/stderr 和退出码表达结果。

- **边界**：参数解析和终端格式不包含领域规则；文件、网络、时钟和进程调用通过清晰适配器进入。
- **错误**：可预期用户错误给出可行动提示和稳定非零退出码；诊断详情进入 stderr 或 debug 模式。
- **测试**：解析/领域 Unit；文件系统或适配器 Integration；调用构建产物/真实入口并断言退出码与输出的 E2E；Bug Regression。
- **安全**：禁止拼接 shell 命令；验证路径、权限和输入大小；默认不覆盖已有文件。
- **分发**：验证从构建产物或打包结果运行，而不只从源码目录运行。

## Library / Package

公共 API 是产品边界。只暴露当前用例需要的稳定符号，并明确版本、兼容和支持平台。

- **边界**：内部模块默认不导出；公共类型、错误和扩展点有明确契约。
- **测试**：内部行为 Unit；序列化、文件或系统适配 Integration；把构建后的包安装到隔离消费者并仅从公共 API 使用的 E2E/consumer test；Bug Regression。
- **构建**：检查包内容、元数据、许可证、入口和源码/类型映射，避免发布测试缓存、秘密或本机文件。
- **兼容**：公共 API 变化说明 SemVer 影响；没有真实消费者需求时不创建复杂插件接口。
- **文档**：README 的最小示例必须由测试或 doctest 验证，避免示例漂移。

## Worker / Event Consumer

最小垂直切片处理一个真实格式的消息/任务，并明确成功、重试、失败和恢复状态。

- **边界**：consumer 负责协议和 ack/nack，应用 handler 负责用例，业务规则不依赖 broker SDK。
- **语义**：明确投递保证、幂等键、去重窗口、重试上限、backoff、毒消息和 DLQ/人工恢复策略。
- **测试**：handler Unit；序列化、持久化或 broker adapter Integration；经实际消费入口执行的 E2E；重复投递和故障的 Regression。
- **可观测性**：记录 message/job id、trace、尝试次数、延迟、处理耗时和最终状态，不记录敏感 payload。
- **关闭与恢复**：验证 graceful shutdown、未完成任务处理和进程重启后的恢复语义。

## Monorepo / 多组件

只有多个组件确实需要一起交付时才采用 monorepo。先定义所有权和依赖图：

- 共享代码通过明确 package/module 公开，禁止跨组件相对路径读取内部文件；
- 依赖从应用指向稳定库，禁止循环；
- 根质量命令编排各组件，组件命令仍可独立运行；
- 缓存和受影响测试不能隐藏完整套件失败；
- 跨组件公共契约增加 Contract/Integration 测试；
- `docs/architecture.md` 展示组件边界和核心数据流。
