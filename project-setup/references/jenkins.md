# Jenkins 适配（按需）

仅在用户或项目已有约定明确选择 Jenkins 时读取本文件。通用命令和阶段策略以 [生产基线](production-baseline.md#8-质量入口与-ci)为准，证据状态以 [验证契约](verification.md#6-验收证据)为准。本文件不要求部署 Jenkins，也不默认引入 Docker 或发布流程。

## 仓库内流水线

将 `Jenkinsfile` 纳入版本控制，保持为仓库命令的薄编排层：

1. 在声明的 Agent/工具链环境中检出待验证版本，记录实际提交 SHA；PR 同时记录目标分支基准及验证对象。
2. 使用项目规定的安装命令；存在有意义锁文件时使用冻结/锁定模式。
3. 调用与本地相同的完整 `verify`/`qa`/`check` 入口，并将失败传播为阻塞结果；不得使用吞错、忽略退出码或继续发布将失败转成绿色。
4. 为任务设置合理超时，保存命令生成的测试和质量报告；失败时也尽可能保留诊断报告。报告缺失或测试未执行不得伪装成通过。
5. 仅在项目需要交付制品时归档并记录其提交标识；推送及部署另行按既定范围配置，不作为验证命令的隐式副作用。

独立检查可在共享命令支持的情况下并行，但必须隔离输出目录和测试资源，并汇总所有结果；不在 `Jenkinsfile` 内重写另一套测试选择或质量阈值。配置检查只证明被检查部分，不替代 Jenkins 中的真实执行。

## PR、主分支与合并保护

使用适合代码托管平台的 Multibranch Pipeline / Branch Source 能力发现分支和 PR。检查现有插件、版本和项目配置后再选择接入方式，不假设任意 Jenkins 实例天然具备 PR 发现与状态回传能力。

- PR 创建、更新：执行完整门禁，回传稳定且唯一的检查名称，并确认结果对应当前候选提交或候选合并结果。说明目标分支更新后的重新验证方式。
- 主分支更新：验证实际合并提交，成功后才进入已约定的制品或发布阶段；不能用这次验证替代合并前门禁。
- 代码托管侧：将对应检查设为必需项，确认失败、缺失或过期结果不能满足合并条件。`Jenkinsfile` 本身不会启用分支保护。
- 外部或不可信 PR：遵循实例的信任策略，不向其提供推送或部署凭证；只有需要外部操作的受信阶段才注入最小权限凭证。

服务器、插件、Webhook、凭证和保护规则属于外部接入条件；只在已有授权范围内配置。缺少条件时仍可生成并检查仓库文件，但将远程运行或保护验收标记为 `[BLOCKED]`，列出缺失条件，不声称接入完成。

## 依据与版本核对

实际生成语法或选择插件前核对当前官方文档与现有实例能力：

- [Using a Jenkinsfile](https://www.jenkins.io/doc/book/pipeline/jenkinsfile/)：版本化流水线、测试报告、制品与凭证。
- [Branches and Pull Requests](https://www.jenkins.io/doc/book/pipeline/multibranch/)：Multibranch、Branch Source 与 PR 支持。
- [Pipeline Syntax](https://www.jenkins.io/doc/book/pipeline/syntax/)：阶段、条件、超时和执行后处理。
